# GitHub Actions CI/CD Documentation

This repository is equipped with complete CI/CD pipelines using GitHub Actions to automate code validation and deployments for Android, iOS, and Web.

---

## 1. Continuous Integration (CI)

The CI workflows run automatically to ensure code quality before changes are merged.

- **Mobile CI (`.github/workflows/ci.yml`):** Runs formatting, code analysis, tests, and validates that mobile configurations are correct.
- **Web CI (`.github/workflows/ci_web.yml`):** Runs identical code validation steps (formatting, analysis, testing) but concludes with a verification step that compiles the Flutter web application (`flutter build web`) to catch web-specific compilation errors.

### Triggers
- **Pull Requests:** Any PR targetting `main` or `develop`.
- **Pushes:** Any direct push to `main` or `develop`.

---

## 2. Continuous Delivery / Deployment (CD)

Deployments are automated and triggered when a pull request is merged into either the `develop` or `main` branches under specific release branch/tag conventions.

### Staging Deployment
- **Trigger:** Merging a pull request into `develop` where the head branch name starts with `v` and ends with `-stg-release` (e.g., `v1.0.0-stg-release`).
- **Mobile Target:** Distributes Android and iOS builds to Firebase App Distribution (Staging). (Workflow: `.github/workflows/deploy_stg.yml`)
- **Web Target:** Deploys the web build to GitHub Pages under the `/stg/` subdirectory. (Workflow: `.github/workflows/deploy_web_stg.yml`)

### Production Deployment
- **Trigger:** Merging a pull request into `main` where the head branch name starts with `v` and ends with `-prod-release` (e.g., `v1.0.0-prod-release`).
- **Mobile Target:** Distributes Android and iOS builds to Firebase App Distribution (Production). (Workflow: `.github/workflows/deploy_prod.yml`)
- **Web Target:** Deploys the web build to the root of the GitHub Pages site. (Workflow: `.github/workflows/deploy_web_prod.yml`)

## 3. Required GitHub Secrets

To allow the **mobile** deployment workflows to run successfully, the following secrets must be added to your GitHub repository (**Settings** > **Secrets and variables** > **Actions**):

### Firebase Authentication Secrets
- `FIREBASE_TOKEN`: Firebase login token generated by running `firebase login:ci`.
- `FIREBASE_SERVICE_ACCOUNT_JSON`: The complete JSON credential string for your Google Cloud service account with Firebase App Distribution admin permissions.

### Android Credentials
- `FIREBASE_APP_ID_ANDROID_STG`: The Firebase App ID for the Android Staging project.
- `FIREBASE_APP_ID_ANDROID_PROD`: The Firebase App ID for the Android Production project.

### iOS Credentials
- `FIREBASE_APP_ID_IOS_STG`: The Firebase App ID for the iOS Staging project.
- `FIREBASE_APP_ID_IOS_PROD`: The Firebase App ID for the iOS Production project.

---

## 4. How to Create Secrets in GitHub

To add a new secret to your repository:
1. Navigate to your repository on **GitHub.com**.
2. Click the **Settings** tab.
3. In the left sidebar, click **Secrets and variables**, then click **Actions**.
4. Click the green **New repository secret** button.
5. In the **Name** field, enter the key (e.g., `FIREBASE_TOKEN`).
6. In the **Value** field, paste the secret value.
7. Click **Add secret**.

---

## 5. Web Deployment Setup (GitHub Pages)

To ensure successful Web deployments to GitHub Pages, complete the following setup in your repository:

1. **Enable GitHub Pages:**
   - Go to your repository on **GitHub.com**.
   - Navigate to **Settings** > **Pages**.
   - Under **Build and deployment** > **Source**, select **Deploy from a branch**.
   - Select the `gh-pages` branch (this branch will be created automatically by the workflow on the first deploy) and set the folder to `/ (root)`. Click **Save**.

2. **Configure Workflow Permissions:**
   - Go to **Settings** > **Actions** > **General**.
   - Scroll down to **Workflow permissions**.
   - Select **Read and write permissions** (required for the deploy actions to push the built web assets to the `gh-pages` branch).
   - Click **Save**.
